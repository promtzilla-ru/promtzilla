# Канон страниц ПРОМТЗИЛЛА

Этот документ фиксирует рабочий стандарт для новых страниц вида «как сделать X с помощью нейросети».

## Основная идея

Каждая страница — это не статья в классическом смысле, а готовая карточка-процесс:

1. Что получится.
2. Что загрузить в нейросеть.
3. Какой инструмент использовать.
4. Какой промпт скопировать.
5. Как выглядит результат.
6. Какие теги/ключевые фразы закрывает страница.

Контент должен быть практичным: пользователь сразу видит пример, копирует промпт и повторяет.

## Типовая структура

Страница строится внутри `.pz-wrap`:

1. `.pz-eyebrow` — `Промтзилла`.
2. `.pz-title` — короткий H2 с переносом и акцентом в `<span>`.
3. `.pz-desc` — 1-2 предложения: что загрузить, какой инструмент, какой результат.
4. `.pz-howto` — пошаговая инструкция на 5-6 шагов.
5. Визуальный блок:
   - `.pz-photo-stack` для пары «вход/результат».
   - `.pz-source-photos` для нескольких исходников.
   - `.pz-ba` для «до/после» внутри карточки варианта.
   - `.pz-result` для одного итогового результата.
   - `.pz-video-wrap` для видео.
6. Секции промптов через `.pz-section`.
7. RU и EN карточки промпта:
   - `.pz-card`
   - `.pz-card-head`
   - `.pz-ru` / `.pz-en`
   - `.pz-card-meta`
   - `.pz-copy`
   - `.pz-card-body`
8. `.pz-tags` — 10 SEO-тегов.

## Форматы страниц

### Одиночный сценарий

Подходит для: удалить фон, определить форму лица, анализ подписи, типаж.

Структура:

- инструкция;
- блок «Пример результата»;
- исходное фото и результат;
- RU-промпт;
- EN-промпт;
- теги.

### Подборка вариантов

Подходит для: выпускной, футбольная карточка, фото с собой в детстве.

Структура:

- краткое описание;
- исходное фото или исходные фото;
- 3-5 секций «Промт N — вариант»;
- в каждой секции: RU-промпт, EN-промпт, до/после или результат;
- теги.

### Многоэтапный процесс

Подходит для: оживить рисунок, документное фото.

Структура:

- шаг 1 с отдельным инструментом;
- шаг 2 с отдельным инструментом;
- `.pz-tool` для группировки по инструментам;
- при необходимости `.pz-tabs` для вариантов;
- видео или финальное изображение результата;
- теги.

## Канон промптов

Промпт должен быть конкретным и повторяемым.

Обязательные элементы:

- что пользователь загружает;
- что нужно сделать;
- какие элементы сохранить без изменений;
- как оформить результат;
- ограничения: без логотипов, без лишнего текста, без искажения лица/предмета;
- язык результата, если есть текст на изображении;
- формат результата: инфографика, коллаж, карточка, фото, PNG, видео.

Для каждой основной карточки желательно давать:

- RU-версию;
- EN-версию;
- одинаковую смысловую структуру.

## Канон визуалов

Для новой страницы нужно подготовить локальные медиа:

- исходное изображение;
- итоговое изображение;
- при подборках — несколько итоговых вариантов;
- при видео-сценарии — исходник, подготовленный результат и видео.

Файлы сохраняются в `public/wp-content/uploads/YYYY/MM` или новом SEO-каталоге, если это новая страница.

Имена файлов должны быть SEO-читаемыми, например:

- `kak-udalit-fon-s-pomoshhju-ii-do.png`
- `kak-udalit-fon-s-pomoshhju-ii-posle.png`
- `kak-podobrat-ochki-s-pomoshhju-ii-infografika.png`

## SEO

Для каждой страницы нужны:

- старый или новый slug;
- title;
- description;
- `image` для карточки и `og:image`;
- `imageAlt`;
- хлебные крошки;
- JSON-LD `BreadcrumbList`;
- 10 тегов внизу страницы.

Если страница заменяет WordPress-страницу, slug должен совпадать с URL из sitemap, чтобы не делать редирект.

### Хлебные крошки и H1

Последняя часть хлебных крошек не должна дословно совпадать с H1/главным заголовком страницы.

Правило вариативности:

- если в H1 написано `с помощью нейросети`, в хлебных крошках использовать вариант вроде `через ИИ`;
- если в H1 написано `через ИИ`, в хлебных крошках использовать `с помощью нейросети`;
- чередовать `с помощью` и `через`;
- чередовать `ИИ` и `нейросеть/нейросети`;
- не держать одинаковую концовку в H1 и в последней крошке.

## Новый рабочий процесс

Когда пользователь просит сделать новую страницу:

1. Определить тему и поисковый интент.
2. Придумать slug.
3. Сгенерировать исходную картинку, если пользователь не дал свою.
4. Сгенерировать результат через промпт или подготовить пример результата.
5. Написать RU и EN промпты.
6. Собрать HTML-блок по канону `.pz-*`.
7. Сохранить JSON в `content/posts`.
8. Сохранить картинки локально.
9. Запустить `npm.cmd run build`.
10. Проверить страницу в `dist/<slug>/index.html`, но публичный адрес отдавать как `/<slug>/` без `index.html`.
11. Обновить карту сайта: добавить новый URL или удалить URL, если страница/рубрика удалена.

## Важные ограничения

- Не возвращаться к WordPress-сайдбару.
- Страница широкая, без правой колонки.
- Не использовать внешние картинки с WordPress-домена, если файл можно положить локально.
- Публичные URL страниц и рубрик всегда писать в формате `https://promtzilla.ru/<slug>/`, без `index.html`.
- При создании, переименовании или удалении страницы/рубрики динамически обновлять sitemap: добавлять новые URL, менять переименованные и удалять те, которых больше нет.
- Не удалять старые URL из sitemap, если страница уже существовала и остаётся доступной как редирект или канонический URL.
- Не делать маркетинговую лендинговую страницу вместо практической страницы с промптом.
